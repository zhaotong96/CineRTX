### 已确认的 ABI/行为约束

- 桥接 `process(input_fence_value)` 的契约：D3D12 队列等待该值，评估完成后信号 `input_fence_value + 1`；若时间线已更靠前则取更大值。
- `D3D12Interop::advance_timeline()` 是唯一的信号值来源，禁止自行硬编码。
- `NgxD3D12Bridge::process()` 内部会先 CPU 等待上一帧 `pending_signal_`，再限制队列深度 ≤2，然后 `queue_wait_fence(V)`。
- `NVSDK_NGX_D3D12_Shutdown1` 在驱动 617.14 上会卡死，**不要调用**；当前只释放 feature/parameter，NGX 运行时保留到进程退出。
- 当前 VSR 输入纹理固定为 `R10G10B10A2_UNORM`，TrueHDR 输出固定为 `R16G16B16A16_FLOAT`。
- TrueHDR FP16 输出是 **linear scRGB，BT.709 primaries，1.0 = 80 nits**（`out/sdk_ref/rtx_video_guide.txt` 已确认）。不要按 10000 nits 解释，也不要在缩放前把 >1.0 的值裁掉。
- 现有 pack kernel 的旧 10000-nit 行为必须保留，`pack_verify` 依赖它；新颜色路径用新 kernel 名称或 v2 入口。

## 4. 剩余任务总表

### P0 — 必须先完成，否则 Gate 2 无法开始

#### P0-1 实现生产级 GPU-only remaster 链路

目标数据流：

```
NVDEC 1080p NV12/P010 (CUDA device ptr)
  → 预处理 kernel：NV12/P010 → R10G10B10A2 输入纹理
  → VSR：1080p SDR → mid_4k_ (RGBA8 4K)
  → TrueHDR：mid_4k_ → RGBA16F 4K (linear scRGB, 1.0=80 nit)
  → pack v2 kernel：scRGB → BT.2020 PQ limited P010 (4K)
  → NVENC HEVC Main10 + HDR10 VUI/SEI
```

全程不出现 host 像素拷贝。桥接内部完成预处理、NGX、pack，核心只拿到 P010 `CUdeviceptr` 交给 NVENC。

**P0-1.2 预处理 kernel（`p010_pack.cu`）**

- 新增 `rtx_yuv_to_rgb10`（或 NV12/P010 两个 kernel），输入 Y/UV 设备指针，输出到桥接输入纹理的 `cudaSurfaceObject_t`。
- 每个输出像素读取 Y 与对应 UV；支持：
  - 8-bit NV12：Y 8-bit，UV 8-bit interleaved；
  - 10-bit P010：16-bit 容器，10-bit 值左移 6 位；UV pitch 按字节。
- 范围：
  - limited：`y' = (Y-16)/219`，`u'=(U-128)/224`，`v'=(V-128)/224`；
  - full：`y'=Y/255`（P010 用 10-bit 归一化），`u'=(U-128)/255`。
- 矩阵：
  - BT.709：`R=Y+1.5748V`，`G=Y-0.1873U-0.4681V`，`B=Y+1.8556U`；
  - BT.2020 NCL：`R=Y+1.4746V`，`G=Y-0.16455U-0.57135V`，`B=Y+1.8814U`；
  - BT.601（可选）：`R=Y+1.402V`，`G=Y-0.344136U-0.714136V`，`B=Y+1.772U`。
- 写入 R10G10B10A2 UNORM：`R` 在低 10 位、`G` 次 10 位、`B` 再 10 位、`A=3<<30`；使用 round-to-nearest-even，`surf2Dwrite` 32-bit。
- 1080p 输出全量写入；像素数约 2.07M，单线程一像素足够；避免每像素 `powf`。

**P0-1.4 桥接编排（`bridge_exports.cpp` + `d3d12_interop.{h,cpp}`）**

- `D3D12Interop` 新增：
  - `cuMemAllocPitch` / `cuMemFree` 符号；
  - CUDA event create/record/elapsed/destroy（`cuEventCreate`、`cuEventRecord`、`cuEventElapsedTime`、`cuEventDestroy`）；
  - 可选：`cuStreamSynchronize` 包装（已有）。
- `BridgeImpl` 新增：
  - `std::mutex remaster_mutex`；
  - `CUdeviceptr p010_buffer`、`size_t p010_pitch`、`size_t p010_bytes`；
  - `RtxNgxRemasterStats remaster_stats`。
- 首次 `remaster` 时分配：
  ```cpp
  cuMemAllocPitch(&p010_buffer, &p010_pitch,
                  width * 2,                 // bytes per row
                  height * 3 / 2,            // rows
                  16);
  ```
  - Y plane = `p010_buffer`，`y_pitch_samples = p010_pitch / 2`；
  - UV plane = `p010_buffer + p010_pitch * height`，`uv_pitch_samples = p010_pitch / 2`；
  - **不要**释放到每次调用；桥接生命周期内复用。
- 每帧顺序（必须严格）：
  1. `interop.bind_context()`；
  2. `V = interop.advance_timeline()`；
  3. 在 `pack_stream` 记录 event `e0`；
  4. 启动预处理 kernel，写 `interop.input().surface`；
  5. 记录 `e1`；
  6. `interop.fence_signal_cuda(pack_stream, V)`；
  7. `ngx->process(V)`（D3D12 队列内部等待 V）；
  8. `interop.fence_wait_cuda(pack_stream, V + 1)`（等待 NGX 信号）；
  9. 记录 `e2`；
  10. 启动 pack v2，从 `interop.output().surface` 写到 P010 buffer；
  11. 记录 `e3`；
  12. `cuStreamSynchronize(pack_stream)`；
  13. 读取事件耗时，填充 `RtxNgxRemasterOutput` 与 stats。
- 注意：`NgxD3D12Bridge::process()` 内部会把信号值提升到 `timeline+1`；只要 V 来自 `advance_timeline()`，`V+1` 就是正确等待值。若中间有其他时间线推进，读取实际 `interop.timeline_value()` 复核。
- 失败路径：device lost 返回 `RTX_ERR_DEVICE_LOST`；NGX 失败返回 `RTX_ERR_NGX`；参数非法返回 `RTX_ERR_INVALID_ARGUMENT`；CUDA 失败返回 `RTX_ERR_INTERNAL`，并写 `last_error`。
- 销毁顺序：`rtx_ngx_bridge_destroy` 必须先等待 NGX `pending_signal_` 完成，再在 interop 存活时 `cuMemFree(p010_buffer)`；**核心必须先销毁 NVENC，再销毁桥接**，否则 P010 缓冲可能在 NVENC 仍持有时被释放。

## 5. 实现细节与易错点（接手人务必阅读）

### 5.1 颜色管线

- TrueHDR FP16 输出不是 PQ，是 **linear scRGB，BT.709 primaries，1.0=80 nits**。
- 现有 pack 的 `input_is_pq=0` 路径把线性值乘 10000 当 nit，这是为旧测试/其他输出准备的；**TrueHDR 必须走 v2 的 80 nit + BT.709→BT.2020 矩阵**。
- 高光可能到 12.49（≈999 nit）；不要先 clamp 到 1.0。
- 输出 P010 是 limited range、BT.2020 NCL、PQ；VUI 的 matrix 应为 BT.2020 NCL（9），不是 BT.2020 CL（10）。
- 4:2:0 色度相位：pack 注释声明 topleft，预处理阶段 UV 采样要与之一致，避免二次相位误差。

### 5.2 CUDA/D3D12 同步

- 预处理 kernel 写的是 D3D12 共享纹理的 CUDA surface；D3D12 端在 `process(V)` 中先等待 V，再 transition 到 SRV，顺序正确。
- NGX 处理完成后 D3D12 队列信号 `V+1`；pack 流必须 `fence_wait_cuda(pack_stream, V+1)` 后再执行 pack。
- 所有 CUDA 调用前 `bind_context`；每次 kernel launch 前 `cuCtxSetCurrent(primary)`。
- 不要在 `process()` 返回后立刻 CPU 读 D3D12 输出纹理；必须等 `V+1`。
- `cuMemAllocPitch` 的 width 参数是**字节**，不是像素；P010 一帧 `height*3/2` 行。
- UV plane 偏移是 `pitch * height`；`uv_pitch_samples = pitch/2`。
- P010 缓冲必须在 NVENC 完成该帧编码后才能复用；桥接同步返回 + NVENC 完成事件已保证顺序，但桥接销毁必须晚于 NVENC 销毁。

### 5.3 NVENC

- `registerInput` 按 `CUdeviceptr` 缓存，P010 缓冲地址稳定，注册一次即可。
- `RtxFrameDesc` 给 NVENC 时：
  - `width=3840, height=2160, format=RTX_PIXEL_P010, bit_depth=10`；
  - `planes[0] = p010 y_plane`，`pitches[0] = pitch`；
  - `planes[1]` 可选填 UV，但当前 `nv_encoder` 只用 `planes[0]` + format 推导 UV 偏移；保持与现有约定一致；
  - `slot_index=0`，不要对桥接缓冲调用 `decoderReleaseFrame`。
- HDR metadata 必须在 `RtxEncoderConfig.hdr` 中显式设置，不能依赖 `applyHdrDefaults` 的旧默认值。
- 异步编码已开启；若吞吐不足，先分段测 decode / NGX / pack / encode，不要盲目改 NVDEC 参数。

### 5.4 容器/CLI

- 现有容器路径 `output_width=info.width`，不会上采样；必须在新路径中显式设置目标 3840×2160。
- 现有 `--frames` 仅 raw 生效；容器路径加上限与进度，否则 1000 帧 Gate 无法复现。
- Muxer 的 `output_info` 必须声明 4K、10-bit、BT.2020/PQ；否则 `colr` 与 VUI 不一致。
- 若源是 8-bit SDR，NVDEC 输出 NV12；不要强行请求 P010，预处理器支持 NV12 即可。
- 若源带 HDR/PQ，VSR 输入不是 SDR，需单独决策；Gate 2.1 只要求 SDR→HDR。
